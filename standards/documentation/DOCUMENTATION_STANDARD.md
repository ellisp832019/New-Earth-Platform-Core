# Documentation Standard v0.1

Each project should document:

- purpose;
- architecture;
- setup;
- build;
- run;
- test;
- release;
- dependencies;
- interfaces;
- troubleshooting;
- version history;
- ownership;
- project contract.

Platform changes that alter schemas, interfaces, dependency semantics, compatibility rules, generated artifacts, or release policy should update the relevant user guide, integration document, standard, or ADR in the same pull request.
